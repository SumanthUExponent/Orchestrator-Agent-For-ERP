# CLAUDE.md

Guidance for Claude Code working in this repository.

## What this repo is

Two things that ship together and are developed together:

1. **The orchestrator** — registry-driven routing for a 45-agent swarm tuned to
   Frappe/ERPNext work. `registry/agents.yaml` is the single source of truth;
   `agents/*.md` are **generated** from it (`node scripts/swarm.mjs build-agents --apply`).
   Never hand-edit `agents/*.md` — the next build overwrites it.
2. **JARVIS** — the voice layer. A local, zero-dependency spoken notification system for
   someone running several Claude Code sessions at once, who is not looking at the screen.

Zero runtime dependencies, deliberately (`package.json` says why). No model calls and no
network anywhere in the speech path. Everything is local and deterministic.

## What JARVIS is for

Announcements exist to answer one question: *does something need me right now, and which
project is it?* Everything else is subordinate to that. The design consequences:

- **Attribution is never optional.** Every announcement names its session. An
  announcement you cannot attribute is worthless, and the rule must not depend on
  live-session bookkeeping being accurate — that is exactly the thing most likely to be
  stale at the moment several projects are running.
- **Silence is a feature.** `Stop` fires after *every* turn. "Done, sir. Three minutes."
  carries no information; it is what made the layer feel noisy. See
  `JARVIS_SPEAK_WITHOUT_SUMMARY` in `voice/config.sh`.
- **Blocked-on-approval is the expensive failure** — three sessions working while a
  fourth waits silently. It jumps the queue, nags, and escalates once.

## Architecture: a queue and a single drainer

```
hook fires ──► voice/jarvis.sh ──► writes ONE file to ~/.claude/jarvis/queue/
                    │                       priority-epoch-pid-random
                    └──► wake_speaker(): mkdir lock, nohup speaker.sh, exit
                                                    │
                    voice/speaker.sh ◄──────────────┘
                    the ONLY process that ever calls the speech engine
```

**Nothing speaks from inside a hook. This is the load-bearing rule.**

macOS does not queue concurrent `say` calls — it plays them simultaneously. Four parallel
sessions therefore produce noise rather than information. The hook's job is to enqueue a
file and exit; exactly one daemon, holding an exclusive `mkdir` lock, drains the queue and
speaks. The superseded first install (`~/.claude/hooks/jarvis.sh`) spoke directly from the
hook and had precisely that bug.

Supporting properties, each of which exists because its absence was a real defect:

- **`mkdir` is the lock**, not `flock` — macOS has no `flock(1)`.
- **The daemon writes its own pid** and re-checks ownership at the top of the loop *and*
  inside the debounce. An orphan that keeps announcing for six seconds after being
  replaced is exactly the overlap the lock exists to prevent.
- **Claim by `mv`, never `cat` then `rm`** — two readers can take the same entry and
  announce it twice; losing an `mv` race is a clean skip.
- **Priority leads the filename** so glob expansion (already sorted) puts urgent items
  first: `0` urgent, `1` nag, `4+` routine. The epoch is a fixed 10 digits so lexical
  sort is chronological.
- **Trailing debounce, not a fixed window.** A one-shot wait collapses only what has
  already arrived, so a burst spread wider than the window straddles it — six specialists
  0.3 s apart produced two chimes. Each round absorbs everything matching and goes again,
  bounded at five rounds so a chattering session cannot defer itself forever.
- **Staleness drops, it does not queue.** A completion announced 90 s late is noise
  (`JARVIS_STALE`). Coming back to the machine must not unleash a backlog.
- **Mute is checked in the daemon as well as the hook.** The nags are generated by the
  daemon's own idle loop and never pass through a hook at all — muting for fifteen
  minutes did not stop it nagging.
- **The farewell is claimed with an atomic `mkdir`.** Closing four terminals fires four
  `SessionEnd`s, and every one removes its own marker before the first bye is claimed.

## The clause budget

**Measured, not a style preference.** At `JARVIS_RATE=172` wpm a word costs ≈ **0.38 s**
of speech. An announcement also carries a frame — the session name and the elapsed time —
which is ≈ **2 s before the clause even starts**.

| Clause length | Total spoken |
|---|---|
| 5 words | ≈ 4.1 s |
| 8 words | ≈ 5.7 s |

**Anything past ~5 s is longer than anyone keeps listening.** That is the whole reason the
agent contract asks for a short clause. Measure with `say -o f.aiff` + `afinfo`; do not
guess. Two registers (naming the session only when 2+ are live) got the worst case from
5.4 s to 1.67 s.

Related measured facts, all in the same spirit — audio design here is measurable, so do
not guess it:

- Layering two different system sounds does **not** make a two-note chime; use one
  percussive atom, pitch-sequenced. `Tink` is the only real one.
- At rate 1.0 `Tink` puts **95%** of its energy in 300–1000 Hz, which is male speech
  formants, so the chime masked the first word. At **1.55** it is 7%.
- `afplay -r` outside **0.4–3.0** produces no sound *and* no error.

## The clause is filtered by an ALLOWLIST, never escaped

Agent output is not a trusted input. It is about to be read aloud and carried through a
pipe-delimited queue line, so `voice/jarvis.sh` reduces it to plain speech with
`tr -cd "A-Za-z0-9 .,;:'-"` and caps it at 140 characters.

**Do not widen that allowlist.** If a pronunciation or phrasing rule needs a character it
forbids, the rule loses. Word separators must be substituted to spaces *before* the
filter runs — `tr -cd` deletes rather than substitutes, so `apps/foo/hooks.py` reaching it
unprepared fuses into one unpronounceable token.

A marker also only qualifies if it is **terminal**: every non-empty line after it is
another marker or the JSON tail. A line anchor is not enough — explaining the contract in
a reply put a mangled half-sentence into a live session's briefing. Documentation must not
be mistaken for data.

## `voice/platform.sh` is the only file allowed to name an OS tool

Every OS-specific call — the speech engine, audio playback, desktop notification, voice
enumeration — lives behind a `jv_*` function in `voice/platform.sh`. Nothing else in the
tree may name `say`, `afplay`, `osascript`, `espeak`, `aplay`, `powershell` or any
equivalent.

**This is enforced by a test**: `tests/voice-audio.sh` check `P2`, "the platform layer is
the ONLY place that names an OS tool". It fails the build on a leak. Cross-platform
support (macOS / Linux / Windows) rests entirely on that discipline, and CI runs
ubuntu × windows × macos on Node 18/20/22 plus shellcheck.

Portability traps already paid for, which is why the rule is absolute:

- **`stat -f` exists on both platforms with different meanings** — a format string on BSD,
  `--file-system` on GNU, where it *succeeds*. So `stat -f … || stat -c …` never falls
  back on Linux. Avoid `stat`; store your own timestamp.
- `#!/bin/bash` → `/usr/bin/env bash`. macOS ships **bash 3.2.57** — no `mapfile`, no
  `$BASHPID`.
- Windows has no execute bit, and a `.sh` path with backslashes cannot be a hook command.
- `trap cleanup EXIT INT TERM` fires cleanup **twice** — TERM handler, then EXIT. Guard
  with a flag plus `trap - EXIT INT TERM`.

## The seven human gates

Verbatim from `registry/agents.yaml` `human_approval_required`. The orchestrator skill
enforces these; agents must refuse and escalate rather than proceed.

1. destructive database changes
2. production deployment
3. destructive git operations (force push, history rewrite, branch deletion)
4. deleting or overwriting an existing skill or agent
5. changing the swarm architecture itself
6. generating a new agent
7. security-sensitive changes

Hitting a gate is the loudest thing JARVIS says, and it names which gate was hit.

## Failure modes that must not degrade

- Missing speech engine → **exit 0, silently.** A broken notifier must never interrupt a
  session.
- Broken `JARVIS_TTS_CMD` template → **fall back to the built-in voice.** A bad template
  must not make the whole layer go quiet.
- No tones generated → stay silent, do not error. Speech still carries the message and
  `doctor` reports the missing set.
- A `hooks.d/` user script → backgrounded, output discarded, exit status ignored. It must
  never be able to stall or kill the daemon.

## Commands

```bash
node scripts/orchestrator.mjs doctor     # swarm integrity, gates, protocol compliance
node scripts/orchestrator.mjs health     # skill registry integrity
node scripts/swarm.mjs build-agents --apply   # regenerate agents/*.md from the registry
node scripts/orchestrator.mjs voice --apply   # install the voice layer to ~/.claude/jarvis

npm run test:all        # node suite + voice-audio + voice-concurrency
jarvisctl demo          # narrated four-session simulation
jarvisctl audition      # speak every variant of every event
```

**Run `npm run test:all` alone.** The suites operate on live state under
`~/.claude/jarvis` and interfere with each other if run concurrently — two parallel runs
produce spurious failures.

`jarvisctl demo` is the highest-value tool here. The individual behaviours are each
verifiable in isolation but the **system** is not: whether four sessions are
distinguishable, whether priority ordering reads correctly when things arrive together,
and whether it is pleasant for ten minutes rather than merely correct once. Its first run
exposed four defects no unit test could see.

## Conventions

- Comments explain **why**, especially where the obvious implementation was wrong. Much of
  this codebase is a record of defects already paid for; do not quietly simplify a comment
  away without understanding what it is guarding.
- Config is **data, not code**. `voice/config.sh` holds `k=v;k=v` tables
  (`JARVIS_NAMES`, and the pronunciation tables) so a user extends vocabulary without
  editing shell. Every value is env-overridable so one session can differ from the rest.
- Sub-agents are **mute**. `SubagentStop` fires once per specialist, so a batch of four is
  four announcements; specialists chime and the count rides into the completion instead.
  Only the main thread speaks.
- Branch discipline: work on `develop`. Never push `uat` or `production`.
