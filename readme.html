01 // Mission

Not a swarm.
A control system.

A growing pile of skills and agents creates a new engineering problem: deciding what not to load, who should act, what can run together, and where a human must stay in command. Most agent frameworks solve the first half. This one is built around the second.

🧠

THE BRAIN

Reads the request, selects the skills, orders the specialists, batches what can run at once, and prices the run before it starts.

🔊

THE VOICE

One queue. One drainer. One sentence at a time. Four parallel sessions physically cannot talk over each other.

🚪

THE GATES

Seven things it will not do without you. Production. Dropped tables. Force pushes. It stops and names which.

The doctrine: you give intent; JARVIS coordinates; specialists execute; verification brings evidence back. The human stays the authority — and nothing here is designed to make the automation feel autonomous. It is designed to keep it observable, bounded and accountable.

03 // Restraint

It refuses to
convene for a typo.

Every extra dispatch is a round trip. A control plane that assembles nine agents for a one-line change is not intelligent, it is expensive. So the first question is always how little swarm does this deserve?

the smallest effective swarm
$ jarvis plan "fix a typo in the readme"
Effort: minimal
  (none) — no agent claims the routed skills.
  Answer this directly. Dispatching would cost more than the task.

$ jarvis plan "drop the audit table and rebuild it"
Human approval required before this runs
  ! destructive database changes
  Nothing here dispatches on its own. This is the line a human signs.
✓

MINIMAL

Typo, label, one field. ≤2 skills, no gates. Often zero agents.

◈

STANDARD

Normal development. ≤4 skills, verify gate.

⚠

FULL

New modules, migrations, platform work. ≤8 skills, sign-off then verify.

04 // The Roster

Forty-five specialists.
Zero duplicates.

Divided by responsibility, and audited by its own governance: the build fails on a duplicate responsibility, a broken dependency, an unreachable agent, or an agent whose job cannot be measured.

WHY A CONTROL PLANE AT ALL?
Because every extra dispatch is a round trip. fast-path-triage decides how much swarm the request deserves; context-broker maps the repository once instead of once per agent; swarm-dispatcher batches the run; result-synthesizer collapses the results; quality-sentinel decides what actually needs deep review. Their entire job is to convene less.
WHO AUDITS THE AUTHOR?
Six passive governance agents whose subject is JARVIS itself — skill-guardian, agent-guardian, routing-auditor, knowledge-guardian, swarm-evolution, efficiency-auditor. They watch for orphan skills, overlapping ownership, wasteful routing and agents that were never selected.
THE HANDOFF PROTOCOL — “done” is a protocol failure
Every agent returns structured fields, not prose: status, summary, confidence, recommended_next_agent, unverified, files_changed, decisions, findings, risks, testing, remaining, verdict, handoff. status is required and is the field the router reads to decide what happens next — which is why the contract names the expensive mistake outright: a false SUCCESS ends the loop, so nothing downstream ever looks again.
05 // Peer Review

The correction should not
have to come from you.

A single pass ships whatever the first attempt produced. Work here goes round: reviewers judge it against the acceptance criteria, and anything they reject goes back to the agent that wrote it, carrying the objection verbatim.

review loop // 3 rounds
round 1   build
round 2   panel judges against the acceptance criteria
          revise → back to the original author, objection verbatim
          re-review only what changed
round 3   last pass

halts on  every reviewer accepts
          the round cap
          any of the seven human gates
          the same objection twice  ← not converging; a human should look

JUDGED, NOT BIKESHEDDED

Reviewers judge against the criteria requirements-analyst wrote. “I would have structured this differently” is explicitly not a defect.

AN OBJECTION MUST HAVE A REMEDY

A revise must name what would satisfy it. An objection nobody can act on is an opinion, and it costs a whole round to find that out.

THREE ROUNDS, NOT MORE

Past three, reviewers are usually disagreeing about taste rather than finding defects — and taste is a human call.

06 // Voice Core

It speaks.
Only when it matters.

You are running four sessions. Three are working. One has been sitting on a permission prompt for six minutes and you have no idea which. JARVIS knows, and says so — by name.

voice channel // live
JARVIS 🔊 "Approval needed on billing, sir. Production deployment."

JARVIS 🔊 "The checkout schema is in, with three line-item tables."

JARVIS 🔊 "Trouble in wt-svc, sir. Four tests are failing on the refund path."

No screen. No notification you will swipe away.
One sentence, in your ear, naming the one project that needs you.
◉

ONE DRAINER

Hooks enqueue and exit. A single lock-holding daemon owns speech — because two say calls do not queue, they play at once.

◌

PRIORITY QUEUE

Blocked approvals jump ahead. Stale news is dropped, not queued. Bursts collapse to one line.

♪

MEASURED, NOT CHOSEN

Chimes are synthesised and loudness-normalised. Speech is budgeted in measured milliseconds — ≈70 ms per letter of prose, ≈224 ms per spelled letter.

WHY NOT JUST READ THE SUMMARY OUT?
Because identifiers do not survive being spoken. apps/shared_lib/hooks.py read aloud is one unbroken nonsense word. A pronunciation layer splits identifiers, speaks filenames as names, spells the acronyms that need spelling, and turns 4m12s into “four minutes twelve” — all from a data table you can extend without touching a line of shell.
WHAT IT WILL NEVER SAY
The elapsed time. It was the one part of an announcement you cannot act on. A turn that reports what changed has already said everything worth hearing. The written record keeps the duration; your ear does not have to.
07 // Evidence

It knows whether
any of it worked.

Most agent systems cannot answer “is this actually helping?” — their health checks validate the config against itself and have never watched a task run. JARVIS keeps a ledger of what each agent actually produced.

jarvisctl ledger // observations, not a score
  agent                   runs   success  partial  blocked   failed   flags
  schema-builder             4         3        1        0        0   1 unverified 1 low-confidence
  test-engineer              2         0        0        0        2
  ui-designer                1         0        0        0        0   1 silent

  totals: 3 success · 1 partial · 0 blocked · 2 failed · 1 unreported
  unreported means the agent did not emit STATUS. That is a protocol
  failure in practice, whatever the registry says.
It records; it does not judge. Judging is a separate job, and a human gates whatever the judgement would change — “generating a new agent” and “changing the swarm architecture” are two of the seven gates precisely so the system cannot quietly rewrite itself.

09 // Doctrine

The rules that keep
it useful.

ZERO DEPENDENCIES

A tool that verifies an ecosystem should not require an install before it can run a security check. No network in the speech path, ever.

DRY RUN FIRST

Installers print their plan before touching the machine, back up settings.json, write atomically, and re-read to prove it parses.

VERIFICATION IS NOT OPTIONAL

Effort caps may drop optional work. They may not drop validation. A failure is reported as a failure, with the output.

MEASURE, DO NOT GUESS

The audio design was settled with afinfo and numpy, not taste. Chime pitch was moved because at rate 1.0 it masked the first spoken word.

COMMENTS EXPLAIN WHY

Much of this codebase is a record of defects already paid for. Do not simplify a comment away without understanding what it guards.

THE HUMAN IS THE AUTHORITY

Seven gates, declared in one place, printed by the planner, and announced by the loudest motif in the set.
